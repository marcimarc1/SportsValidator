# Developer guide for the backend



## Deployment on an instance
To launch the ENTIRE stack :
- Install docker **As explained here** : https://docs.docker.com/engine/install/ubuntu/#install-using-the-repository. In particular you need to check that you can run `docker compose` in **2** words 
- Run `build.sh`
- You can now connect to it by entering the instance's ip in your favorite browser



## Deployment on local host
- Install docker as described on the website for your machine. In particular you need to check that you can run `docker compose` in **2** words
- Run `build.sh`
- You might want to adjust the port used by `rust_backend` in `docker-compose` deployment
- You can now connect to it by entering `localhost:<port nunber>` in your favorite browser

You can clean the unused space generated by docker by running `clean.sh`



## Docker
- The `Dockerfile` specifies how the docker container for the web server should be built
- The postgres container is simply pulled from DockerHub

Other useful docker commands :
- List running container : `docker ps -a`
- List all existing containers : `docker container ls -a`
- List all existing images : `docker image ls -a`
- Inspect all docker disk space : `docker system df -v`
- To attach to a docker compose container : `docker compose exec api sh`



## Sqlx
Structural changes to the database are managed by migration files, which sqlx library makes sure they are only ever ran once. These files have to follow a particular naming convention, which is why it is easier to create them via the command :
`sqlx migrate add <name>`
