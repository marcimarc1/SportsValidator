# Readme

### Running the Web App

The Webapp was only developed and tested on a Linux (Ubuntu 20.4) environment, but in theory it should work anywhere regardless of the operating system.

1. Install node and npm (I am currently using node 10.19. and npm 6.14.4).
See for example https://docs.npmjs.com/downloading-and-installing-node-js-and-npm or simply install both of these through your normal package manager.

2. Clone this repository.

3. Navigate into the frontend folder of this repo (where this file is located) and run the following commands:
    - `npm install` to install all dependencies.  
    In case that does not work you can try deleting frontend/package-lock.json and try again.  
    If there are any dependency issues you can try running `npm audit fix`.  
    
    - `npm start` to build the app in development mode. This should automatically run the app locally and open a browser window. The app is usually served by default at localhost:3000.  
      
In case the HOST environmental variable is set, the app might not be served at localhost. Try unsetting it temporarily by running `unset HOST` in your terminal or change your bash configuration in order to not set it (see https://stackoverflow.com/questions/53912056/npm-start-on-new-create-react-app-build-returns-elifecycle-error for more information and instructions).
    
Currently, the Tracking Editor requires a reload (just refresh the page manually) in order to show the first frame in the tracking editor.

For making a production build of the app have a look at https://create-react-app.dev/docs/deployment/
    
    
### Overview over the Code

This Project was created with the create-react-app command that autogenerates some of the boilerplate files and code. Here is an overview over of the project structure and all important files for further development:

- **public/**:  
Contains the Favicons (the small symbol the webbrowser shows in the tab for each website; in the project they were generated with https://favicon.io/favicon-converter/) and the standard mostly autogenerated documents such as index.html, the parent HTML file for the complete app.
- **src/**:  
The sourcecode for the webapp (all the JS and CSS files) as well as data and assets such as icons, fonts and pictures used in the webapp.
  
  - **index.css**: Basic CSS properties for the whole project, such as e.g. fonts.
  - **App.js**: Handles the routing and inserts the React components required to display the current part of the site depending on the URL.
  - **components/**: All self-developed React components and their CSS files that are used in App.js; Every JS file is named after the component it contains and all CSS files are named after the hierarchically highest components they are imported in; These CSS files are then also often used in all child components in order to group the CSS together.
    - **layout/**: All components that are part of the layout and used throughout multiple pages of the webapp (in this case currently only the Header).
    - **pages/**: All components that belong to the various subpages of the app, in case of multiple components grouped into folders for each page of the webapp with all JS and CSS files used there.

- **data/**: All the data used by the app which is supposed to be provided by the backend in the future; Since there is currently not yet a backend, image files as well as exemplary data from backend calls in the form of JSON files are stored here. All images and the tracking_data.json file were provided from the chair for the development of the app, the remaining files were created manually with exemplary imaginary data.

- **fonts/**: The files for all fonts used in the app that are not standard and included in webbrowsers already.

- **icons/**: Symbols and icons in SVG format. All icons stored here are form www.SVGBox.net.

- **pictures/**: All pictures used throughout the webapp for design purposes (as opposed to images that are data shown in the app which would therefore be located in the /data folder).
  - **dark_football_field.jpg**: The background picture from the starting page. A free to use and edit stock photo that was edited with GIMP to remove some players and make it darker.
  - **green_grass_texture_512x512.png**: A grass texture that can be optionally used as background in the subpages /games and /analysis/\<id\>. Currently the code to do so is commented out in favor of a grey background (see "GRASS BACKGROUND" comments in CSS files of these two subpages for infos on how to change that).


### Backend Integration

In general, all locations in the code that require changes in order to integrate the backend (mostly calling it or sending changes to it) are marked with a "TODO BACKEND" comment. Usually, they also already contain commented out pieces of code that show an exemplary call to the backend (e.g. a possible function name with parameters to call it as well as which variable to assign the returned values to). The code directly after these comments then usually assigns dummy data to the variable where the backend data should be saved and hence should be checked for parts that need to be removed.  
Moreover, the JSON files in the src/data/ folder contain exemplary backend responses that contain the data currently shown in the backend. They also serve as examples of how the backend should return its data so that it can be used in the webapp without any further changes. Once the backend is finished and integrated, these files can and should be removed from the code.  
My recommendation (which is also commented in the code in more detail) would be to create a "Demo" backend call that can serve this data in order to implement a demo section of the webapp where the functionality can be tested without the user having to create an account and upload a video.
